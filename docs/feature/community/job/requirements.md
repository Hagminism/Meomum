# 일자리 게시판 기능 구현

## 구현 요구사항

- 커뮤니티 게시판 중 일자리 게시판의 경우, "사용자의 구인 글 + 한국관광공사 관광인 채용 정보 API에 등록되어있는 구인 글"로 내용을 구성한다.
- 관광인 채용 정보 API에 대한 정보는 아래와 같다.
    - OpenAPI 활용 방법: https://api.visitkorea.or.kr/?loginFlag=sso#/useTursmGuide
    - 엔드포인트: https://apis.data.go.kr/B551011/tursmService
    - 인증 키의 경우 이미 발급되어있으며, 작업 과정에서 필요한 경우 개발자에게 요청하여 획득한다.
    - 호출 시 어떤 데이터를 획득할 수 있는지 파악하기 위해 구현 전에 테스트 호출을 진행해야한다.
- API 호출을 통해 채용 정보를 가져올 때, 각 지역 게시판에 해당하는 구인 글을 적절하게 표시해야한다.
    - 지역 코드와 시군구 코드로 지역별 검색이 가능하므로, 적절하게 매핑하여 해당하는 게시판에 글을 표시해야한다.
        - ex) 서울시 영등포구에 해당하는 코드를 가진 채용 정보의 경우, 서울시 영등포구 일자리 게시판에만 표시되어야한다.
- 사용자가 작성한 구인 글과 한국관광공사 관광인 채용 정보 API에 등록되어있는 구인 글은 시각적으로 구별되어야한다.
    - 다른 게시판처럼 [community_post_card.dart](/Users/ihagmin/Meomum/lib/feature/community/presentation/component/post/community_post_card.dart)를 사용하지 않는다.
    - 두 형태의 글은 서로 다른 별도의 모델로 저장한다.
    - 사용자 글은 좋아요·댓글·신고·수정·삭제 등의 기능을 정상적으로 제공하며, 한국관광공사 글은 제공하지 않는다.
    - 한국관광공사 글은 인증 뱃지를 표시하여 사용자 글과 직관적으로 구분할 수 있어야 한다.

## 추가 구현 요구사항

### API 데이터 동기화 및 노출 기준

- 채용정보 목록은 `empmnInfoList`, 채용정보 상세 내용은 `empmnInfoDetail`을 사용한다.
- 지역·직종·공통 코드는 `code` API를 통해 조회하고, 앱에서 필요한 코드명과 함께 관리한다.
- API 데이터의 변경·삭제·비노출 상태는 `syncList`를 활용하여 동기화한다.
- API 채용정보는 `empmnInfoNo`를 고유 식별자로 사용하며, 동일한 채용정보를 중복 저장하거나 중복 노출하지 않는다.
- API 키는 앱 소스 코드나 클라이언트 요청에 노출하지 않고 서버 또는 안전한 환경변수에서 관리한다.
- API 응답을 화면에서 매번 직접 호출하지 않고 서버 또는 저장소에 캐싱하여 트래픽을 관리한다.
- `showYn` 값과 관계없이 API가 반환한 채용정보를 게시판에 노출한다.
- `showYn`은 원본 데이터의 표출 상태로 보존하되, 마감 여부는 마감일(`rcptDdlnDe`)을 기준으로 판단한다.
- 마감일이 지난 채용정보는 목록에 남기고 마감 상태로 표시한다.
- 상시채용(`ordtmEmpmnYn=Y`)은 마감일 대신 `상시채용`으로 표시한다.
- API 데이터의 등록일시·수정일시 또는 마지막 동기화 시각을 기준으로 최신성을 표시할 수 있어야 한다.

### 지역 매핑 및 데이터 예외

- 채용정보는 `regnCd`와 `signguCd`가 모두 일치하는 지역 게시판에만 노출한다.
- 지역 코드가 없거나 매핑할 수 없는 채용정보는 임의의 지역 게시판에 노출하지 않는다.
- 주소 문자열만으로 지역을 추정하여 다른 지역 게시판에 노출하지 않는다.
- 기업명, 급여, 마감일, 로고 등 선택 데이터가 누락되어도 목록 화면이 깨지지 않아야 한다.

### 모델 및 목록 상태 분리

- 사용자 구인글과 한국관광공사 채용정보는 서로 다른 도메인 모델과 저장소를 사용한다.
- 한국관광공사 채용정보에는 최소한 채용정보번호, 기업명, 채용제목, 근무지, 급여, 급여형태, 고용형태, 경력조건, 모집인원, 마감일, 상시채용 여부, 등록일, 수정일, 원문 URL을 저장한다.
- 사용자 구인글 목록과 API 채용정보 목록의 로딩·새로고침·페이지네이션 상태를 분리한다.
- API 채용정보를 기존 `CommunityPost` 모델로 변환하여 저장하지 않는다.

### 사용자 구인글 작성 정보

- 사용자 구인글은 기존 커뮤니티 게시글 기능과 별도로 구인 목적에 필요한 정보를 입력할 수 있어야 한다.
- 구인글 작성 시 제목, 모집 내용, 근무 지역을 필수 정보로 제공한다.
- 급여, 급여 형태, 고용 형태, 근무 시간, 모집 인원, 모집 마감일, 지원 방법 및 연락처는 선택적으로 입력할 수 있어야 한다.
- 입력되지 않은 선택 정보는 목록 및 상세 화면에서 자연스럽게 생략한다.

### 화면 및 상호작용

- 사용자 구인글과 한국관광공사 채용정보는 서로 다른 카드 UI를 사용한다.
- 카드에 `사용자 작성`, `한국관광공사 제공` 등 데이터 출처를 표시한다.
- 한국관광공사 제공 뱃지는 데이터 출처를 의미하며, 채용기업이나 채용공고의 별도 검증을 의미하지 않는다는 점을 명확히 한다.
- 한국관광공사 채용정보 카드에는 기업명, 근무지, 급여, 고용 형태, 마감일 또는 상시채용 여부를 우선 표시한다.
- 한국관광공사 채용정보 상세 화면에서는 원문 URL을 통해 관광인 채용정보 페이지로 이동할 수 있어야 한다.
- 사용자 구인글에는 좋아요·댓글·신고·수정·삭제를 제공하고, 한국관광공사 채용정보에는 해당 기능을 제공하지 않는다.
- 사용자 구인글과 API 채용정보를 구분하여 조회할 수 있는 필터를 제공하는 것을 고려한다.
- 사용자 구인글만 존재하거나 API 채용정보만 존재하는 경우에도 각 데이터 유형에 맞는 빈 상태를 표시한다.

### 오류 및 테스트

- API 호출 실패, 응답 지연, 호출 제한 초과 시 사용자에게 적절한 안내를 표시하고, 가능한 경우 마지막으로 동기화된 데이터를 제공한다.
- API 데이터 파싱 실패와 지역 코드 매핑 실패를 앱 전체 오류와 구분하여 처리한다.
- API 동기화가 여러 번 수행되어도 동일한 `empmnInfoNo`의 데이터가 중복 생성되지 않아야 한다.
- 지역 코드가 일치하지 않는 채용정보가 다른 지역 게시판에 노출되지 않는지 검증한다.
- `showYn=N`, 마감 채용정보, 상시채용 정보가 각각 올바르게 처리되는지 검증한다.
- 사용자 구인글과 한국관광공사 채용정보의 카드 UI, 상세 이동, 제공 기능이 서로 올바르게 구분되는지 검증한다.
