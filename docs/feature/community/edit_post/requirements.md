# EditPost 화면 구현

## 1. 구현 요구사항

- 디렉터리 구성은 다음과 같이 정한다.
    - /feature/community 디렉터리 하위에 별도의 /feature/edit_post 디렉터리 1개를 추가 구성한다.
    - 커뮤니티: /feature/community(이미 정의되어있음)
    - 게시글 수정: /feature/community/feature/edit_post
- 커뮤니티 하위 화면 경로는 다음과 같이 정한다.
    - 커뮤니티: /community(이미 정의되어있음)
    - 게시글 상세: /community/post-detail/:postId(이미 정의되어있음)
    - 게시글 수정: /community/post-detail/:postId/edit-post
    - 게시글 수정 페이지는 게시글 상세의 하위 중첩 라우트로 설계한다.
- 게시글 상세 페이지에서 우측 상단 점 세 개 버튼을 눌러 메뉴를 연 뒤, '글 수정' 눌렀을 때 게시글 수정 페이지로 이동해야한다.
- 게시글 수정 페이지는 게시글 작성 페이지의 UI를 그대로 가져다 사용한다.
    - 게시글 상세 페이지에서 게시글 수정 페이지로 이동할 경우, 게시글 작성 페이지의 UI(입력 필드)에 글 내용이 입력된 상태로 화면에 표시되어야한다.
        - ex) 원본 글 제목이 '안녕하세요', 본문이 '반갑습니다'이고 사진 2장이 첨부되어있을 경우, 앞 내용이 모두 입력된 상태로 화면에 표시되어야한다.
    - [community_write_screen.dart](/Users/ihagmin/Meomum/lib/feature/community_write/presentation/screen/community_write_screen.dart)
    - 필요한 경우 Design Pipeline 스킬을 이용하여 추가 디자인을 요청할 수 있어야한다.
- 사용자는 원하는 내용으로 게시글을 수정할 수 있어야한다.
    - 기존 글 내용과 비교하여 아무 내용도 바뀌지 않았을 경우에는 db에 저장 시도를 하지 않아도 된다.
    - 변경 사항이 있을 경우 사용자가 업로드 버튼을 누르면 db 내용 갱신을 시도한다.
        - 갱신(내용 및 이미지 수정)은 게시글을 작성 시처럼 트랜잭션으로 처리한다.
        - 게시글 작성 시처럼 이미지 업로드에 실패할 경우 보상 처리를 해주어야한다.
    - 내용 수정 및 업로드에 성공했을 경우, 이전 화면으로 돌아오면서 새로고침하여 수정된 내용을 표시해야한다.
